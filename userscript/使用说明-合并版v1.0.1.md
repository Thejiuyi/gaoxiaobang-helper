## ⚠️ 装之前先做这一步：**删掉篡改猴里的旧版**

这一版改了 `@namespace`（`yuanYue-byte` → **`Thejiuyi`**）。

篡改猴用 **`@name` + `@namespace`** 当脚本的唯一标识 ⇒
**它会认为这是一个「全新的脚本」，而不是旧版的升级** ——
旧版**不会**被替换掉，而是**留在篡改猴里**。

**两版共存会互相抢跳章**：旧版按它自己的规则跳走，新版看起来「修复无效」。
（这正是这个脚本反复踩过的坑 —— 面板上写版本号、脚本自带的多实例自检都为排查它。）

其中三条最要紧的断言不是「面板长什么样」，而是「**它不能捣乱**」：

1. **面板不能被站点的「按文字找按钮」逻辑看见。**
   站点的 `findByText()` 会把含「继续 / 完成 / 提交」的短文本元素当成按钮去点。

   站点靠「还有 N 次 / 有效提交次数」这类字样读测验次数；
   面板里一律写「**还剩** N 次」，避免被误读。

   | 结果页 `/submission/` | `⏸ 测验完成 · 得分 100.00；本次答对 3 题、答错 1 题（共 2 题）` |

2. **点一下按钮看完整详情**（第一次点看详情，第二次点才是暂停/继续）：

   ```
   本套测验你已经提交过了 —— 不会再自动作答。

   测验编号：100005
   得分：100.00 / 满分 100.00 分
   本次答对：5 题（共 5 题）
   剩余机会：1 次
   交卷时间：2026-09-21 22:00
   ```

3. **★ 更重要的：脚本现在认得出「这卷已经交了」，一个字都不会再点。**

### ⚠️ 为什么第 3 条是必须的（不是顺带做的）

已提交的卷面上，选项**看起来和没交时一模一样**：

```html
<!-- 已提交（带 true/checked）—— 和未提交的 <i class="gxb-icon-radio"> 是同一套前缀 -->
<i class="gxb-icon-radio checked true" answer_id="800001"></i> A. 307
```

⇒ 判定「这页有哪些题可作答」的那套逻辑（读 `.answer-wap` + 找 `answer_id`）
**照样读得出 5 道题** ⇒ 如果不管，脚本会把它当成一份**新卷**再答一遍。

某一套**只剩 1 次机会**时（真机：`有效提交次数3次，已提交2次`）。
真机上 `#quizSubmit` 已经不在了，「交卷」这一步会失败 —— 不会真烧掉机会，但是：

- 脚本会照 AI 的答案**去点只读的卷面**（把已经批改好的勾选改乱，你看着莫名其妙）；
- 右下角会报「需手动：交卷失败…」—— 而事实恰恰相反（**这卷 100 分，早做完了**）；
- 万一站点哪天在已提交页上也留着提交键，那就成了**真·烧掉最后一次机会**。

⇒ 这一版加了一道守卫，而且**放在「读卷」之前**：认得出已提交 ⇒ 立刻停手。

### 它靠什么认（不是押一个类名）

按「**任意一条成立就算已提交**」，四条特征互相独立：

1. 页面上有**看得见的**成绩区块（`.quiz-submission-bg` / `.quiz-sub-more` / `.quiz-sub-finish`）
2. 页面内联数据里 `submission.status === "submitted"`（你的页面上确实有 `var submission = {…}`）
3. 卷面已被批改（有 `.true` / `.error` 标记）**且没有提交键**
4. **没有**提交键、但有「再做一次」按钮

> ⚠️ 第 1 条必须**真的看得见**才算数（`display:none` 的隐藏容器不算）。
> 否则站点在答题页上预留一个隐藏的成绩容器，就会让脚本**误以为已交卷** ⇒
> **整卷自动作答静默失效**（你只会觉得「脚本坏了」，还查不出原因）。
> 这一条专门写了测试（test-v2519 D 组）盯着。

## 三、v2.5.18：**真正修好了「返回内容为空」—— 关掉 AI 的「思考模式」**

### 你遇到的现象（以及上一版没解决的原因）

你点开按钮详情后，露出了这段原始响应：

```
"model": "deepseek-flash"
"content": ""                                      ← 正文是空的
"reasoning_content": "We need answer JSON only…"   ← 思考字段却有内容
```

**注意 `model` 那一行**：你已经按上一版的建议换成了 `deepseek-flash`（名字里没有"推理"字样），
**问题却一模一样。** 这说明上一版给你的建议**方向错了** —— 这是我的问题，这版来纠正。

### 真正的原因：不是「模型是推理模型」，而是「思考模式默认开着」

查了 DeepSeek 官方《思考模式》文档，原文写着：

> **「思考模式默认打开，且 effort 默认为 `high`」**

而且——**那份官方文档里的示例模型名，恰好就是 `deepseek-flash`。**

也就是说：

| 上一版的说法 | 事实 |
|---|---|
| 有 `reasoning_content` ⇒ 这是**推理模型** | ❌ 不对，`reasoning_content` 是**服务端**行为 |
| 换个非推理模型就能解决 | ❌ 模型名跟这事**无关**，换了也没用 |

**「思不思考」是平台服务端的一个开关，不是模型的名字。** 默认就是**开着**的，
所以模型会先「思考」一大段，把额度用完，然后**没额度写正文了** —— `content` 就是空的。
但 HTTP 是 200、地址和 Key 全对，所以你看到的只是「返回内容为空」。

### 这一版做了什么

**脚本现在每次请求都带上「关闭思考」的参数**（`thinking: {"type": "disabled"}`，官方格式）。

- **你不用再换模型** —— 现在这个 `deepseek-flash` 就能用。
- 是**每次请求都带**，不是失败后才补带。因为如果只在重试时带，
  第一次请求仍然会白烧一次额度、还要多等一轮，而那次请求可能本来就是唯一的机会。
- 这个开关在**菜单里**（`关闭思考模式`），默认**开**。极少数平台不支持这个字段并报 400，
  那时候把它关掉即可。

**附带好处**：思考模式下 `temperature` 参数是不生效的（官方文档明说）。
关掉思考后，脚本设的 `temperature` 才真正起作用。

### 诊断文案也修了

以前失败时会说「**这个模型是【推理模型】**」—— 现在改成正确表述，
并且给的建议从「换模型」改成「**关思考**」。

### ✅ 你现在该怎么做

1. **删掉篡改猴里的旧版本**，装上 v2.5.18。
2. **刷新**那个测验页（必须刷新，否则跑的还是旧脚本）。
3. **不用改任何设置**，直接自动做测验。
4. 如果还是失败 → 点右下角按钮看详情，把弹窗内容发我（现在弹窗里带的证据足够定位）。

> ⚠️ **首次使用建议先点菜单⑤「测试 AI 连接」** ——
> 它的第 2 步会按整卷的真实形状测一次，能提前告诉你行不行。

## 五、v2.5.16：**连接测试现在能测出「为什么自动做测验会失败」**

### 你遇到的现象

> 那个测验页自动做测验时，右下角报错「**ai 调用失败：返回内容为空**」，
> 可是我**测试 ai 连接没问题**。

**「测试连接没问题」是真的，但它证明不了「能做测验」。** 这两件事走的是**两条不同的路**：

| | 菜单⑤ 测试连接（旧版） | 自动做测验时真正发的请求 |
|---|---|---|
| 问的内容 | `只回复两个字：收到`（**9 个字**） | **整卷题面**，通常 1000~4000 字 |
| 要求格式 | 随便说点什么都行 | **必须输出 JSON** |
| 模型思考量 | 极少，额度绰绰有余 | **暴涨**（问题越长，思考越多）|
| 结果 | ✅ 通过 | ❌ 额度被思考吃光，**正文是空的** |

**根因**：你用的多半是一个**「推理模型」**（如 `Qwen/Qwen3-8B`、DeepSeek-R1 系列）。
这类模型会先「思考」再作答，而**思考要花多少 token 无法预知**。
问题短的时候思考少、额度够；问题一变长（整卷），思考量暴涨，
`max_tokens` 在思考阶段就被吃光，于是 `content` 是**空的** ——
但 HTTP 是 200，地址、Key、模型名**全都是对的**。这就是「连接测试通过」的来源。

### 这一版做了什么

**菜单⑤「测试 AI 连接」改成两步**：

1. **第 1 步**：还是原来的短问题（验证地址 / Key / 模型名通不通）。
2. **第 2 步**：**按整卷测验的真实形状**再发一次
   （同样长的题面 + 同样要求 JSON + 同样的 system 尾巴）。

然后如实报三种结果：

| 结果 | 含义 | 你要做什么 |
|---|---|---|
| ✅ 全部通过 | 两步都拿到了正文 | 可以直接自动做测验 |
| ⚠️ **半通** | 短问题通、长请求失败 | **不是连接问题**，是额度不够 ⇒ **换模型**（见下）|
| ❌ 连接失败 | 连最短的请求都没通 | 按提示查 Key / 地址 / 模型名 |

**「半通」的提示里会写清**：这**不是**连接问题、为什么短问题会通过、
以及**你现在能做的动作** —— 菜单 ④ 把模型名换成一个**非推理模型**
（`deepseek-chat` / `qwen-plus` / `glm-4-flash` 这类）。

### ✅ 你现在该怎么做

1. 装上 v2.5.18，刷新页面。
2. 点篡改猴菜单 → **⑤ 测试 AI 连接**。
3. 看弹窗：
   - 说「⚠️ 半通」→ **菜单 ④ 换模型**（换掉 Qwen3 / R1 这类推理模型），再测一次。
   - 说「✅ 全部通过」→ 直接去那套卷子自动做测验。

> ⚠️ **那一套现在还剩几次机会？** 脚本在这一步失败时是**安全**的 ——
> 它**不会拿残缺答案凑合交卷**，所以你的次数**没有被浪费**。
> 但请**先测好连接再去做**（见第三节的完整流程）。

### 附：为什么脚本不自动「多给点额度」就完事

脚本**已经**会自动放大额度重试（`500 → 2000 → 6000`）——
但推理模型的思考量**没有上限保证**，加大额度可能仍然不够，只是让你多等几轮。
**换一个非推理模型是最省事、最可靠的办法**。

## 七、为什么这事要认真修（不只是改文案）

**「错题本」这一页很危险。**

实测（真机 DOM 抓下来跑的）：错题本页上有 **5 个 `.question-item`、5 个 `.answer-wap`**

v2.5.18 之前，在那个观察器里：

1. 能定位到「当前题」✅（`.question-item` 命中了）
2. 但拿不到「正确答案」元素（错题本没有答案标记）⇒ 走 `return`，**侥幸没点**

⇒ **没点，是靠运气，不是靠设计。** 一旦站点改版给错题本加上答案标记，
旧版就会去点它。这是隐患，所以 v2.5.18 在**页面级**把它堵死了

**实测证据**：错题本页注入 v2.5.18 后跑 2.6 秒（主循环跑 2 轮以上），

## 九、整卷测验自动作答：它会怎么做（完整流程）

   {"answers":[{"question_id":"900001","answer_ids":["800001"]}]}

5. **交卷**：点「提交」→ **轮询等最多 3.2 秒** → 点确认弹窗的「确认」

   - **【v2.5.19】如果成绩是直接渲染在答题页上的**（真机实测就是这样），

## 十一、改过的判定逻辑（给以后维护的人）

### 5.1 页面作用域判定 `pageScope()`（v2.5.18 新增）

```js
function pageScope() {
    const path = location.pathname;
    // A) 整卷测验页 —— 该跑（必须放在 /quiz 列表页之前，用 \d+ 精确区分）
    if (/\/quiz\/\d+/.test(path)) return { run: true, ... };
    // B) 章节页 —— 该跑
    if (/\/unit\/[^/]+\/chapter\/[^/]+/.test(path)) return { run: true, ... };
    // C) 已知非学习页 —— 不跑（公告/成绩分析/测验列表/作业/考试/讨论区/错题本/拓展内容）
    for (const [seg, label] of NOT_STUDY) { ... return { run: false, hint: '本页不适用 · ' + label }; }
    // D) 目录页 —— 不跑（v2.5.11 既有守卫，保留自己的文案）
    if (isCatalogUrl()) return { run: false, hint: '目录页 · 不自动跳章' };
    // E) 认不出 ⇒ 【默认放行】
    return { run: true, why: '未识别的页面形态 → 按旧行为放行' };
}
```

### 5.2 ⚠️ 为什么是「白名单 + 默认放行」，而不是「不是学习页就拦」

这是**失败方向**的选择（本项目反复吃亏的那条）：

| 写法 | 站点改 URL 形态时 | 可发现性 |
|---|---|---|
| 「不是章节页/测验页就拦」 | **整个脚本静默空转**，什么都不干了 | ❌ 不可发现（最坏） |
| 「**认得出**那 8 个非学习页才拦」（本实现） | 只是**退回旧行为**（按钮又显示「运行中」） | ✅ 用户看得见、报得出来 |

跟 `isCatalogUrl()`（v2.5.11 目录页守卫）是**同一个思路**。

### 5.3 ⚠️ 为什么必须写在两个地方

`renderPauseButton()` **每轮都跑，而且直接写 `textContent`**，
完全绕过 `updatePauseButtonHint()` 的优先级机制。所以：

- 主循环里的守卫（`if (!_scope.run) { … return; }`）负责**不做事**
- `renderPauseButton()` 里的判断负责**按钮文案不被盖回「运行中」**

两者缺一不可 —— 只在主循环拦，按钮 1 秒内就会被盖回去，用户还是看到「运行中」。

### 5.4 判定为什么只能认 URL（不能认 DOM）

真机抓下来的 10 份 DOM，用脚本自己的 `detectPageKind()` 跑，结果：

| 页面 | `detectPageKind()` | 关键 DOM |
|---|---|---|
| 公告 / 成绩分析 / 考试 / 讨论区 / 拓展内容 | `unknown` | 无题 |
| **测验列表** `/quiz` | **quiz** | `.quiz-item` × 18 |
| **作业列表** `/assignment` | **quiz** | `.quiz-item` × 6 |
| **错题本** `/wrong` | **quiz** | `.question-item` × 5、`.answer-wap` × 5 |
| 课程目录 `/unit` | `doc` | `a.chapter-info` × 82 |

⇒ 三个页面被误判成 quiz，其中错题本与答题页**结构几乎一样**。
**光看 DOM 分不开「列表页」和「答题页」**，只能认 URL。

另外：目录页里的章节链接是 `href="javascript:void(0)"`（真机原文），
**没有 `/chapter/` 路径** ⇒ 也不能靠 DOM 反推「这是不是学习页」。

## 十二、本次排查用过的方法（可复用）

1. **先抓真机 DOM，不猜类名。** 把 10 个页面各存一份 HTML
   （`browser-demo/_pages/`），后续所有判定都拿它跑。
   （判据：锚点要选**真机原文**，不能凭常识猜 —— 本项目在类名上猜错过一次。）
2. **从真源码抽判定函数去跑，不用自己的复述版。** 用「编译探针」定边界
   （把候选文本逐步延长，直到 `new Function` 能编译通过）——
   手写状态机在正则/模板串面前很容易抽飞，而且**抽飞了还会报"成功"**。
3. **测「不该跑」的页面时，除了断言按钮文案，还要断言「一个元素都没点」。**
   光断言文案，脚本仍然可能在背后点东西。
4. **变异测试**：用旧版（v2.5.13）跑新测试 → **4/32 通过**，
   28 条变红，红的正是「错题本 / 课程公告按钮写着运行中」这些**用户报的原症状**。
   这证明断言有判别力，不是永真。
